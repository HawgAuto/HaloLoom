# HaloLoom v0.1.2 — native-agent runtime and Qwen qualification

This coordinated release packages the native Codex runtime, optimizer lifecycle repairs, Quark export safeguards, and matching component sources. Existing v0.1.0/v0.1.1 tags remain available; no production service is activated by publication.

## Included fixes

- GEAK crash/interruption/deadline results remain failures instead of being synthesized as successful `no_gain` outcomes.
- Hyperloom resumes interrupted internal sweeps, honors explicit resume concurrency settings, and carries the accepted GEAK overlay through optimized-arm evaluation.
- ROCm visibility is normalized for the installed Ray runtime without silently changing conflicting device selections.
- Native Codex 0.153.4 includes the qualified scoped AMD sandbox support. Native hook integration, permission compaction and container Git identity support are included.
- Quark restores missing tensors only after checking the space needed for an atomic weight rewrite; failed preflight leaves originals intact.
- Evaluator wheels, current framework-source bindings and native CLI selection are included in the offline build inputs.

## Evidence and limits

The native GEAK workflow completed with nine completed turns, six replayed turns, and no failed turns. The parent then accepted the real result, performed the concurrency sweep and completed CLOSE. The sweep recorded three successful pairs and no failed pairs: mean speedup **1.169×**, best pair **1.1704×**. The client concurrency values were **4/2/1**, while engine capacity remained **one active sequence**. These results describe this quantized Qwen workload—not pure decode, broad model accuracy, or a general batching-capacity claim.

The final published vLLM image was exercised with the original native serving launcher: health/model discovery, normal chat (`READY`), streaming (`READY` plus `[DONE]`), tuning engagement and bitwise-parity checks passed. The server was stopped after qualification. HIP and Triton offline gfx1151 compilation succeeded inside the final images without host framework sources or GPU execution.

A post-optimization **advisory** TraceLens candidate review failed with `CodexSessionUnavailableError`; no unreviewed output from it is promoted or included in the accepted serving recipe. No new full-model accuracy score is asserted. Optional AITER attention and sampling remain outside the qualified scope.

The inherited sealed functional matrix remains byte-preserved historical evidence, not a claim that every target was rebenchmarked here. Exact source pins, image identities and runtime evidence are in `qualification/receipts/release-runtime-v0.1.2.json` and `manifests/components.json`.

## Installation and reproducibility

Use the normal `install.sh` workflow in the repository. An existing host agent CLI is detected; no host Python dependencies or agent CLI are installed by that workflow. The qualified Codex binary runs inside the images.

The three release assets are the Hyperloom wheel, offline build-input archive, and `SHA256SUMS`. The build-input archive includes the pinned native Codex source archive. Model weights, host credentials, caches and campaign logs are not release assets. Low-bit packs remain separate.
