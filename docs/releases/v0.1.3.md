# HaloLoom v0.1.3 — Quark runtime fixes

HaloLoom remains a model-agnostic toolkit. This release fixes runtime problems in the Quark image; it does not distribute an optimized model or a model-specific optimization campaign.

## What changed

- Quark's native extension is compiled during the image build using its installed source and matching Torch/ROCm toolchain. Normal users no longer need to compile it inside a protected package directory at runtime.
- The vLLM backend bundled inside the Quark image now preserves the native embedding handler for excluded vocabulary embeddings and tied output heads, rather than selecting a linear-only handler.
- The documented full build entrypoint includes the native-extension finalization step. Source hashes guard the adapter patch, and image-build tests run as UID 1000.

The original Quark source files and installed package versions in both Python environments remain unchanged. These are generic runtime repairs, not architecture-specific model tuning.

## Update

From a clean existing checkout:

```bash
git pull --ff-only
./scripts/install.sh --agent codex
```

Use `claude` or `hermes` instead if that is your installed CLI. The installer reads `v0.1.3` from `manifests/components.json` and selects the matching public image tags.

The corrected Quark image is:

```text
ghcr.io/hawgauto/haloloom-quark-rocm10-gfx1151:v0.1.3
ghcr.io/hawgauto/haloloom-quark-rocm10-gfx1151@sha256:b4bf033c34b9acfbf2eb548c80cb3686c0eab3049093c1ef9a46ff14339f5f3f
```

## Verification and scope

The image passed non-root import tests with a read-only filesystem and JIT fallback disabled, plus five CPU embedding/dispatch regressions. Real quantization, native export validation, and bundled serving/evaluation were exercised as the normal non-root user. The source suite passed 436 tests, with two skips and five passing subtests.

Models were used only as test fixtures. Model weights, quantized exports, model-specific settings, optimization results, and campaign reports are not release payloads. Detailed fixture evidence stays outside this repository. Runtime verification is not a guarantee that a user's chosen quantization meets their model-quality goals.

Only the Quark image changes. The standalone vLLM, SGLang, and optional AITER images keep their exact v0.1.2 digests under v0.1.3 aliases. The embedding repair described here is in Quark's bundled evaluation backend; no new standalone-framework handoff or full optimizer qualification is claimed.

The original v0.1.2 tool wheel and source-input archive remain immutable and are linked through `manifests/release-assets.json`. This release adds only a model-neutral runtime verification receipt and its checksum, described in `manifests/release-assets-v0.1.3.json`. See [building](../BUILD.md) for the source-input and native-finalization distinction.
